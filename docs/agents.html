AI operating manual

Agents

If an AI is pointed at Brackets, it should learn the smallest path first, keep the public syntax locked, and let Datastar stay the engine under the framework mask.

Core identity

  • No build step.
  • HTML-first.
  • Datastar-powered.
  • Backend agnostic.
  • Portable-folder first.

Non-negotiable rules

  1. Do not introduce a build step.
  2. Do not replace Datastar with a second reactive engine.
  3. Do not change the public Brackets syntax.
  4. Keep .api remote and .data local-first.
  5. Keep Node in this repo as one host adapter, not a requirement.

Teach Brackets in this order

  1. UI with .view and .html
  2. Behavior with .logic
  3. Model code in .data
  4. Optional shared authority in .api
  5. Datastar underneath all live behavior

Why Brackets does not need a plugin API

Most things a framework would call a plugin are already just normal Brackets files, browser modules, workers, or host bridges. That keeps Brackets simpler, more portable, and easier to teach.
