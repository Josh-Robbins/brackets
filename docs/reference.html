Reference

This is the public Brackets contract. The syntax is locked, Datastar stays underneath, and this page captures the core model you can count on in v0.95.

File types

File typeMeaning
.viewWhat page exists.
.logicHow the app behaves.
.apiHow the app talks to a backend.
.dataHow the app defines and talks to local models and persistence rules.
.htmlActual templates, pages, layouts, and components.
.jsonSimple structured storage.
.yamlHuman-editable config or content storage.
.dbFile-backed database storage.

Routing

  • router.logic provides the router engine and global hooks.
  • view.route gives page-level routes.
  • /routes/*.logic lets large apps add grouped route logic.
  • Brackets supports file-based and logic-based routing together.

Page manifest

The required core is still small: id and html. Everything else stays additive: route, layout, logic, aliases, preload, auth, assets, api, and data.

Context and lifecycle

ctx is the canonical runtime object. Keep it grouped, teachable, and small.

  • ctx.route
  • ctx.state
  • ctx.action
  • ctx.api
  • ctx.data
  • ctx.nav
  • ctx.cache
  • ctx.auth

Transport

Brackets keeps transport HTTP-first and Datastar-compatible. read() is the live SSE path. request(), get(), create(), update(), patch(), and delete() stay HTTP by default.
